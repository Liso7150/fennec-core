# Changelog

All notable changes to fennec-core, the shared Python runtime and Rust client/glue
workspace the rest of the suite is built on.

The sections below carry the published tag each change actually shipped in
(`Liso7150/fennec-core`, `v0.1.0` … `v1.0.0`). An earlier revision of this file
numbered the same history on a 1.x/2.x ladder that was never published; those
tags still exist locally (`v1.2.0` … `v2.0.0`) and each one points at the same
commit as a published `v0.x` tag — local `v2.0.0` and published `v0.9.0` are the
same commit. `v0.2.0` was never released here (the ladder goes `0.1.0` →
`v0.3.0`), and `v0.7.0` carries only version-string edits over `v0.6.0`. Dates are
the GitHub release publish dates.

## [1.0.0] - 2026-11-26

This release replaces the 2026-11-24 build and supplies the reasoning-effort plumbing required by
the matching JetBrains plugin. Measured on the working tree: **563 Python tests passed, 1 skipped**.

### Added
- Shared `reasoning_effort` configuration (`auto`, `low`, `medium`, `high`) with
  `FENNEC_REASONING_EFFORT` override; ACP turns pass it into `loop.new_session`, and the setup
  wizard preserves it

## [1.0.0] - 2026-11-24 (superseded)
This build was replaced by the 2026-11-26 release.
Measured on the working tree: **560 Python tests passed**
(1 skipped) and **69 Rust tests passed / 0 failed across 16 suites** in
`fennec-core/src` — core is two lanes in the results hub. Counts come from
`benchmarks/artifacts/hub/RESULTS.json` (updated 2026-11-24T13:27:28Z) and are
generated by the hub (`python benchmarks/results.py` in the suite root), not
hand-maintained.

### Added
- Guarded `GET /api/capabilities` advertises the supervised coding contract —
  `supervised-agent`, `tool-execution`, `per-call-approvals`, `agent-polling`,
  workspace jail/write, explicit unsandboxed shell, and PWA hosting — and
  `Core::capabilities()` deserializes it through the shared Rust capability type
  (`754d539`). Native shells and the PWA now gate coding on features instead of
  guessing from a health response
- `fennec setup --download-model` fetches the Fennec-ready
  `Liso/qwen36-35b-colibri` int4 safetensors checkpoint (22.78 GiB) into the
  chosen models root and selects it only after all 50 required files are present
  and nonempty (`7542b5c`). The optional `fennec-core[models]` extra supplies
  `huggingface_hub`; workers are capped at eight, tokens come from `HF_TOKEN` in
  the environment only, and dry runs or ordinary setup never download anything
- Typed event envelope system with domain models: `events.py` plus
  `tests/test_events.py`
- `CodingAgentClient` and SSE stream support in `fennec-client`
  (`src/fennec-client/src/coding_agent.rs`, wired through `http.rs`) — the client
  the CLI's `fennec agent` verbs and the desktop app use
- Suite clients routed through that Rust agent rather than per-surface HTTP glue
  (`53d3bbc`, 2026-11-22)
- First-party browser outlet lane replacing the third-party one: `liquid.py`
  (decision model, one forward pass, calibrated probabilities), `snapshot.py`
  (indexed DOM nodes), `webagent.py` (decide-execute-observe loop) and
  `web_driver.py` as its process boundary. The lane is Fennec's own loop driven by
  a Liquid **d1** model — hosted `d1.2` via `LIQUID_API_KEY`, or open-weight
  `d1-2B` via `LIQUID_ENDPOINT`
- Opt-in MCP connector endpoint: a bearer-gated, workspace-jailed Streamable HTTP
  surface for read-only external integrations (`mcp_server.py`)
- `updater.py`: background updates from `Liso7150/fennec-core` GitHub releases,
  SHA-256 verified before applying, with an experimental channel
- Every engine knob spelled `FENNEC_*`; the `COLI_*` alias is gone from the engine
  launch path (kept only as a legacy secret name the redactor knows)
- ACP agent improvements and expanded coverage in `loop.py`, `server.py`,
  `tools.py` and `src/fennec-client/src/agent.rs`; these Python references are the
  separate orchestration/compatibility service, not the Rust/Axum front door
- `fennec-client` parses the outlet status instead of guessing at it
- CI workspace tests expanded to macOS and Ubuntu; `fennec-napi` workspace member
  committed so the CI workspace loads
- Preflight goldens carry their own fixture
  (`benchmarks/workloads/model/config.json`)

### Changed
- Core is the canonical supervised PWA/API host on `127.0.0.1:8787`; the Rust
  coding-agent service is a separate auxiliary/chat process on `127.0.0.1:8788`.
  Missing supervised capability fails closed rather than silently substituting
  chat-only execution
- The Python package is flattened to the repo root and `convert.py` answers what
  `scan_models` got wrong: a folder with `config.json` and a `.safetensors` is not
  necessarily servable
- The engine child is pinned under `FENNEC_*` names only; the only `COLI_*`
  handling left is the defensive scrub of a stale `COLI_API_KEY` from sidecar
  environments and the redaction key for legacy configs — neither is set anew
- `backend: "auto"` pins no backend flags, deferring to the engine's own vendor
  policy (NVIDIA=cuda, Apple=metal, otherwise vulkan); an explicit backend pins all
  three vendor flags to `0` and then the chosen one to `1`
- The preflight report renders the way CPython does
- Docs cite the Rust launcher in fennec-cli instead of the deleted Python package
- Rust workspace moved from `rust/` to `src/`; the desktop shell moved out to
  fennec-desktop and the CLI out to fennec-cli, and the workflows for the moved
  crates were retired
- The duplicate core-local `fennec-economy` crate was removed; context budgeting
  lives in its own repo, and `src/` carries six crates. `fennec-napi`, committed so
  the CI workspace loaded, is no longer in the workspace
- The coding-agent HTTP client accepts all 2xx statuses, not only 200
- The pipe section quotes measured numbers, not the pre-gate ones

### Removed
- The Colibri engine launch path: `engine.py` spawns only the native Rust binary
  under `engine_root` (no `c/coli` Python launcher, no interpreter wrapping),
  `config.py` no longer accepts a `~/Colibri` checkout as an implicit engine root,
  and `setup_wizard.py` accepts only a Fennec tree with a built binary
  (`ENGINE_FILES`, the legacy engine report and the `vulkan_loader_present()` host
  probing are deleted). Colibri stays a historical benchmark comparator only
- The deleted browser outlet's driver and its tests; the tests that named it now
  assert it is refused, and the pre-removal redaction golden is kept beside its
  replacement so the change is auditable

### Fixed
- Approval timeouts and missing sessions end the turn immediately instead of asking
  the model to retry; an exact duplicate rejected call stops with
  `permission_denied`, and the default per-call review window is 15 minutes, so a
  disconnected client cannot trigger repeated waits or misleading write results
- Stable updater downloads now require the exact `SHA256SUMS` asset and a valid
  matching basename digest before staging; missing or malformed manifests fail
  closed
- Compaction stats aligned between the Rust bridge and Python: `context.py` reports
  the token-saving fields (`files_summarized`, `helper_chats_summarized`,
  `screenshots_summarized`, `token_savings`, `webpages_extracted`) the bridge expects
- Cross-platform path handling in `src/fennec-client/src/suite.rs`
- A delivered path is read against the workspace the run started in
- A tool call the model spells as prose is recognised, not only JSON
- Engine named correctly in the 503 the desktop app shows
- Token-stream matrix workflow (block YAML, winner script); `wry 0.57` builder API
  (`new()` + `build(&window)`) — that webview desktop shell was later moved out to
  fennec-desktop and replaced by the native GPUI app
- API route slashes normalized to handler names, and the CI smoke URL's trailing slash
- `python updater.py --help` ran the update instead of describing it: the entry
  point tested only for `--experimental` and ignored every other argument, so a
  conventional help flag reached the network and the `.new` write. `-h` and
  `--help` now print the usage and exit before `update()` is called
